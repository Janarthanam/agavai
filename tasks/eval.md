# Assistant eval

A scored, repeatable eval of Agavai as a personal assistant, split into capability sections. Design: [docs/eval.md](../docs/eval.md).

Status: implementation complete and validated, awaiting commit (no commit requested). First run: `evals/results/20261009-1829/report.html`. A person still reviews case expectations and confirms open decisions 1 to 4. Earlier status: waiting for input. The design is a proposal and nothing is built. Scope is decided: the eval includes work not yet built. Four decisions in `docs/eval.md` under "Open decisions" need a person before cases are written: which router the totals use, which actions need a spoken yes, where the eval lives, and the expected answer for requests such as "play some music". Five more (speed budgets, footprint budgets, recorded speech, where computer use is tested, language) are needed only when their section is built.
