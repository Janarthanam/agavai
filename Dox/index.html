What this reference describes

This documents the inspected repository working tree at base commit f44544c, including changes already present from other sessions. It is a source snapshot, not a check of your installed desktop. flow.md governs runtime behavior, audio.md governs recognition, and ui-design.md governs the native surface. Older Voxtype, GTK and silence-timer descriptions in architecture.md are superseded on the automatic assistant path. Context classification and setup changes were in progress at inspection time and are labeled accordingly. No end-to-end latency SLA is established. This reference runs offline; it does not call models, open a microphone, or execute desktop tools.

    Design choices

    Why the pipeline has this shape

    ChoiceWhat it buysCost / alternative
    Streaming ASR with EOULive hypotheses; a learned end token commits the sentence. No timer waits after recognition.Cache, frontend and reset alignment must be correct. File transcription is simpler but hides words until stop; energy/Silero endpointing can mistake pauses for finished requests.
    Separate ASR → GGUF → TTSEach model has a focused job; local CPU defaults fit the repository's target desktop.Serial stages add latency. The v2 decision record discusses speech-to-speech models but found no drop-in tool-capable replacement within its machine budget; those evaluations are historical, not refreshed here.
    One session processSimple ownership; serial turns; context dies when the user dismisses.Cold ASR load per session. A resident agent would retain context but complicate microphone ownership. F9 exclusion is still unenforced.
    One native overlayCompact orb leaves other apps usable; expanded transcript and results share cancellation and selection.Depends on the Omarchy shell. The earlier GTK fallback is superseded. This browser reference cannot validate native layer-shell focus.
    Tool heads before completionAt most eight advertised schemas by default; smaller context for Qwen.Routing can miss a head. Jev sends committed utterances remotely; keyword routing avoids that hop. One extra-head retry is implemented.
    Direct allowlisted functionsVoice actions use the existing DISPATCH; bounded subprocess argument lists; no shell supplied by the model.Tools share process trust and are not sandboxed. MCP exposes the same functions externally, with an extra protocol boundary.
    Atomic UI snapshotsQML sees complete JSON; dismissed session ids suppress late writes.No event queue or replay; rapid writes collapse into the latest snapshot. Typed ask and listening can contend for the same file.
    Warm Kokoro + fallbacksCPU speech model can outlive a session; eSpeak and notification preserve a reply path.Cold synthesis and playback add delay. eSpeak and typed playback do not use the listener's interruptible Kokoro cancellation path.

    Deployment & reliability

    A desktop application, with one model service

    Install and start

    1. Keep the repository or extracted light bundle in a permanent directory. Installed CLI launchers symlink into it.
    2. Setup reviews ~/.config/agavai/config.toml first, checks an executable llama-server, then downloads the selected all / llm / voice / none assets.
    3. Install verifies the GGUF exists, registers the QML plugin and app, and enables and restarts agavai-llm.service.
    4. The plugin lives in Omarchy's shell. A user invocation starts a detached listener; it owns an ASR worker and capture subprocess. Kokoro is started on demand.

    Limits are bounds, not SLAs

    Person / concurrency
    One voice session; one turn at a time; llama-server --parallel 1. No queue or measured requests/sec.
    Router
    2 s request timeout; at most two initial heads; eight schemas by default.
    Local completion
    120 s per HTTP call; six tool rounds; 512 completion tokens; 8,192 context tokens by default.
    ASR
    160 ms of new mel features per encoder step. Intra-op threads = 1. Upstream latency figures reported in audio.md are not desktop end-to-end measurements.
    UI / context
    Meter at most 10 Hz; five visible turns; up to 40 display items; 8 KiB text preview; at most 24 stored non-system messages.
    Speech
    30 s socket timeout; cold startup polls for about 10 s; one-shot synthesis timeout 120 s. Server accept idle timeout 600 s.

    Failure and cancellation behavior

    TriggerActual responsePractical limit
    Overlay summon failsInvocation returns an error before starting a listener.No second native renderer is launched.
    Missing ASR assets, runtime or microphone framesVisible error; listener returns failure; capture and worker are cleaned up.No Voxtype or timer fallback on automatic listen.
    Silence / empty EOUWorker ignores empty EOU; capture remains open.Enter on empty speech can say “I did not hear anything.”
    Jev key / timeout / HTTP failureKeyword heads, unless fallback is none. An empty successful choice also falls back when enabled.Router decisions are not logged in the snapshot.
    llama-server down / HTTP failureHealth check gives a service-start hint; LlmError is surfaced; listener can return to listening.No HTTP retry policy. Context classification adds a call on subsequent turns.
    Missing head / unknown tool / invalid argsOne head-attach retry; otherwise dispatcher returns result text describing the error.Schema advertisement is guidance, not strict per-turn permission enforcement.
    CancelMark dismissed-session, create listen.cancel, then SIGTERM the identity-checked listener; suppress late snapshots.In-flight blocking HTTP, synthesis or tools may finish before checks resume. Cancellation does not roll back completed actions.
    Speech failsKokoro → eSpeak → notification after configured preference.Kokoro listener playback is interruptible; blocking eSpeak and typed playback can complete before cancel is observed.
    Concurrent entry pathsListener startup guard checks a pid/start token and an exclusive lock.It is not a F9 microphone lock or an ask/listen snapshot-writer lock. No system-wide exclusivity claim.

    Where to look when something stalls

    agavai status reports coarse state, model selection and HTTP health. systemctl --user status agavai-llm and journalctl --user -u agavai-llm inspect the resident model service. $XDG_RUNTIME_DIR/agavai/ui.json holds the latest phase, transcript and clipped tool rows. Kokoro uses kokoro-serve.log / kokoro.log. ASR stderr is retained in a bounded parent buffer; detached listener stdout/stderr are redirected to /dev/null, so diagnostic coverage is incomplete. No distributed tracing or metrics service is implemented.
