# Agavai voice and results interface

How a session moves from shortcut to spoken reply is specified in [`flow.md`](flow.md). This file is the interaction and presentation spec for the overlay.

Open [the interactive prototype](ui-prototype/index.html) in a browser. It uses simulated microphone levels, partial transcription, and tool results. No microphone, model, desktop tool, or external network is accessed. Video playback accepts a local file. Use Alt+M in the prototype; Super+Ctrl+M remains the native shortcut.

## Interaction

The shortcut opens an orb-only listening presence in the configured corner of the active monitor (`[overlay] placement`, default bottom right) and starts microphone capture immediately. Compact mode hides all text and results and takes no keyboard focus, so the user can continue working. The orb never moves: click it to expand, and the sheet grows out of that corner around it; click it again, or use the − button beside the status line, to minimize without stopping capture or discarding the session. Clicking another window also minimizes without cancelling capture, except while a canvas is on screen: results and on-screen answers stay up until the user minimizes them or a new request clears them. With Hyprland's focus following the mouse, moving the pointer would otherwise hide an answer as soon as it appeared. A canvas cleared while another window has focus minimizes the view. The × button sits on the orb’s upper outer corner in both views and dismisses and cancels directly. Right-clicking the orb also dismisses and cancels. A newly returned canvas expands automatically in place, including lists, images, media, status cards, rich content, and empty results. Transcripts, ordinary spoken replies, errors, and updates retaining the same canvas respect manual minimization. The presence is a borderless orb. Its size and motion follow smoothed input amplitude from the same capture used for transcription. A gentle breathing ring shows that the microphone is listening even during silence. When a session starts listening, one short rising chime plays with the first ring, so the start is audible without looking. Reopening the microphone between turns stays silent. Speech strengthens the ring and orb movement. The listening ring disappears during processing, playback, errors, and idle; an idle orb stays still.

In the expanded view, partial transcription occupies the primary line under the listening label, above the orb. Replace the current partial utterance as recognition revises it; append only finalized segments. Never turn each partial into a conversation turn. While the surface listens for a follow-up, the primary line belongs to the next utterance and the finished request stays visible as “You said …” above its result and answer, so the user can check what was recognized. A pause submits the utterance; the same shortcut or Enter submits immediately. Escape cancels capture and pending work before dismissing the surface.

The surface stays open and listening until the user dismisses it, in either compact or expanded mode. Silence does not close the microphone or send noise to the model. Isolated finalized controls are handled locally first: `Agavai` silently clears conversation/results and pending actions while keeping the same listening session; `Yes` or `Continue` executes a prepared action once, and `No` discards it. The explicit confirmation question is shown/spoken before the action, with no Done state until an actual tool result. A control word within longer speech is ordinary input; partials and EOB never trigger it. Unbound Yes/No get local clarification, while unbound Continue goes to the model. Other finished utterances after the first use the local model to classify their relation to the earlier conversation. A follow-up keeps the earlier messages and results; an unrelated request clears prior turns, canvas results, answer, and completion before generating the new answer. The orb returns to listening after either kind of turn. A new invocation still starts a blank session.

A recording ([recording.md](recording.md)) reuses the same corner and orb. While recording, the orb draws a steady red ring instead of the breathing one; paused, the ring turns amber and stops moving. Minimized, a timer chip sits beside the orb. It is the one exception to compact mode showing no text, because a recording must never be invisible, and it stays outside the input region. Expanded, the sheet shows the committed lines with their times, marks, Pause or Resume, Mark, and Stop; the line still being heard is in the voice row with a hint to say "Agavai stop". Assistant actions are hidden. × and Escape stop and save. When the recording stops, its review opens in the sheet. The review shows the title and date, Play, back 10 s, a track with mark ticks that seeks on click or drag, and the speed (1×, 1.5×, 2×). Clicking a line plays from its time, and the playing line is highlighted. Double-clicking a line opens it for correction, and Enter saves it through `agavai recording correct`. Corrected lines carry a dot, "Show heard words" shows what was recognized, and "Open folder" opens the recording's folder. The Recordings list opens a recording in the same review, with a way back to the list. While recording, the bar icon carries a dot and its tooltip gives the time; clicking it stops and saves.

A finished desktop action, such as setting the wallpaper, shows a Done line with what changed. The spoken reply says the same thing. A failed action shows Not completed with the reason. Looking something up does not use that line. The listening ring remains, with the hint that Escape dismisses.

The surface transitions from Listening → Working → Results. During tool execution, show a human-readable activity such as “Searching files”, with the tool identifier available in details. Results appear in the expanded view of the same surface instead of opening a second window. A brief spoken answer accompanies the richer screen content. An answer that reads better than it sounds, such as a list or steps, appears the same way: a titled Markdown answer opens the expanded view, and only a one-sentence summary is spoken. Short answers stay spoken only.

Results persist until dismissed, replaced by new results, or cleared when the context response identifies a new conversation. Escape closes the surface. A new conversation resets selection, transcription, tool status, and previous previews without changing the listening session identity. An invalid or failed context response shows an error and retains the earlier results and model history for a retry. Partial speech never triggers a context decision.

## Result presentation

| Result | Primary presentation | Selection preview |
| --- | --- | --- |
| File or folder | Icon, name, parent path, relevant metadata | File thumbnail, text excerpt, or folder summary |
| Markdown answer | Readable headings, paragraphs, lists, code, links | Full-width answer; no redundant list |
| HTML answer | Sanitized semantic content | Full-width content; no scripts or arbitrary embed |
| Image | Thumbnail rows with names and dimensions | Larger image, caption and source |
| Video | Named media rows with duration when known | Local player with controls; no autoplay |
| Desktop status | Compact labeled values | Relevant details |
| No matches | Plain empty state and new-request action | No blank preview pane |

Arrow keys move selection and update the preview. Enter opens the selected item through a specific allowlisted action. Merely selecting an image must not set the wallpaper. An explicit “Set wallpaper” action is separate. Showing a result does not imply its action has succeeded. Tool activity is secondary to useful content; raw JSON and arguments belong in an expandable details view.

## Omarchy and Hyprland implementation

Use the existing Quickshell plugin and `agavai-chat` layer namespace. Do not draw the listening surface with the menu or popup widgets (`BorderSurface`, `Color.menu`, `Style.font.menuFamily`). That chrome is what makes the overlay look like a native Omarchy popup. Results text, spacing, and the results sheet use `Color.background`, `Color.foreground`, and `Style.font.family`. The orb keeps its own spectrum so it stays recognizable. The card behind the words and the orb uses the Omarchy background at high opacity, with `Color.foreground` and `Style.font.family`, so the surface stays in front of the desktop and follows the theme. Respect display scale, active-monitor placement, reduced motion, and a bounded scrolling results area. Listening is only as wide as the words and the orb. The orb occupies the same 80-logical-pixel square, inset 28 logical pixels from the two edges of its corner, in both compact and expanded views. The expanded sheet shares that corner and grows toward the middle of the monitor: to roughly 680 logical pixels wide, clamped to the available monitor width and height with the same edge margins. Next to the orb is the voice row: status, the words, the Done line, the spoken answer, and Send now, aligned toward the orb. Results and actions sit on the far side of that row, so on a bottom placement they are above it and on a top placement below it. If the sheet must clip, it clips the far side and keeps the voice row beside the orb. Narrow screens stack the list above the preview.

Only the expanded native surface requests on-demand keyboard focus so Escape can cancel listening and Enter can optionally send immediately. It must not request exclusive focus, which traps pointer input in Hyprland. Losing native window focus minimizes the surface without cancelling capture, unless a result canvas or pipeline help is visible. Minimizing releases keyboard focus. Compact pointer input is bounded to the 80-logical-pixel orb square in its corner; expanded pointer input is bounded to the sheet. Validate multi-monitor focus and cancellation manually in Hyprland; a browser cannot validate layer-shell behavior.

There is one native renderer: the Quickshell overlay. The desktop app entry is an invocation command for this same surface, not a separate GTK window. “Type instead” reveals an inline text field on the results sheet.

## Data and wiring

The expanded status row has a small, keyboard-accessible `?` button for version and pipeline help. It toggles a bounded scrolling panel in the results area; closing it restores the existing results. Escape closes help first, and another Escape dismisses the session. Minimizing or starting a new session closes help. Like a result canvas, open help stays visible through focus loss. Reading help does not pause capture or suppress incoming snapshots. Arrow/Page keys scroll help; Enter in the help body does not submit speech or open a hidden result. The orb and compact input region stay unchanged.

Help labels the running session writer's Python version and source revision at first UI construction, including a modified-source marker when applicable; installed packages without Git metadata report that the revision is unavailable. It describes the session's loaded configuration, never rereads the saved config, and never inherits version/pipeline information from a previous writer. Configured input, endpoint, router, primary/fallback brains, actions and reply order are separate from latest-turn execution. Execution reports routing bypass or its actual fallback source, context/model requests, escalation, missing-head retries, tool dispatch, and the selected speech engine/playback outcome. Brain labels describe the requested model/backend, not independently verified server weights. Typed requests explicitly bypass microphone/ASR/endpointing. During recording the panel instead explains that content bypasses the assistant pipeline. An older snapshot without metadata shows an unavailable message rather than guessing.

The expanded status row also shows the short session ID and whether it is saved
or temporary. A saved session opens a bounded history selector with New session
and explicit Resume actions. Browsing history preserves listening and results;
Escape closes history first, and minimizing closes it. History and pipeline help
are mutually exclusive. Selecting a session dismisses the old listener and waits
for its action/audio finalization; after five seconds it reports a retryable wait
instead of killing the process. Typed requests continue the selected saved
session (`ask --session`), stopping its microphone owner first. Resume rebuilds
recent turns and canvas from durable events, labels interrupted outcomes unknown,
and requires fresh instructions for interrupted or previously pending actions.
Audio-save warnings are shown beneath the status row without changing capture.
The full timeline and source/audio availability are available through
`agavai session show ID`; the snapshot is a bounded projection.

While recording, `ui.json` carries a `recording` block, and a saved recording is a `recording` canvas holding only its folder path. The overlay reads that folder's `recording.json` itself, so a saved correction shows without the listen session rewriting the snapshot. `ui.json` now carries `transcript: {text, final}`, a typed `display` block with ordered items and a presentation `id`, formatted `answer_html`, and a session identifier. `level_db` drives the mic. Cancellation marks the session and suppresses late snapshot writes; the overlay notifies the controller. Snapshot writes remain atomic. Partial transcript updates are accepted only during listening.

Typed results should include `id`, `kind`, `title`, `subtitle`, preview content/source, source tool, and explicit allowlisted actions. Markdown and HTML are distinct content types. Sanitize HTML, restrict link/media schemes, preserve local paths as data, and use an allowlisted file-open action. Do not execute tool-returned commands. The browser prototype deliberately renders a small escaped Markdown subset; it is not a production Markdown or HTML engine.

The harness emits full tool results and typed status in `tool_completed` events before building the model-facing text. `ChatUi.on_harness_event` projects them through `ChatUi.tool_done()`; headless consumers receive the same results without a snapshot. Typed results (files, folders, images, videos, and the other lists) are sent to the model as kind and readable name. List replies briefly summarize the results and point to the canvas instead of enumerating every filename. Filename-derived spoken labels omit extensions and replace underscores and hyphens with spaces; explicit human titles are retained. Echoed filenames and paths are replaced with those labels. The overlay keeps the full path for opening and preview. `canvas.display_for()` normalizes file search, wallpapers, themes, windows, status, reminders and explicit Markdown/HTML blocks. File search's JSON path list and a newline-path fallback are supported. File paths are encoded into local media URIs; text previews read at most 8 KiB per item. Preview selection is independent of opening. `agavai ui-open` validates the current session, selection and supported file type before invoking `xdg-open` with a fixed argument list; folders can open in the file manager. Executables and desktop launcher files are excluded.

Live words come from the streaming local recognizer; simulated words in this prototype do not supply that capability. Keep the final recognizer authoritative, and handle partial revision, cancellation, missing devices, and slow recognition explicitly. The existing microphone meter drives the native orb now.

## Delivery boundary

The single native Quickshell overlay implements this design. Super+M, the desktop launcher, and the bar icon invoke automatic listening. Super+Ctrl+M remains an alias. Invoking again during a request raises the same widget without starting or stopping capture. Existing capture and speech services remain the source of audio and transcription. The browser prototype is still an isolated simulation for design exploration.

Native results persist until dismissal or a new request; no separate pin control is needed. The expanded surface uses on-demand keyboard focus, so Escape dismisses while it is focused. Clicking another window releases that focus and minimizes the surface unless a result canvas or pipeline help is visible. Compact mode releases focus and offers a visible × close button within the orb’s input area, right-click dismissal, or the existing bar cancel action. The default listening surface is the bottom-right orb; `[overlay] placement` in `config.toml` moves it to `bottom-left`, `top-right`, or `top-left`, and the snapshot carries that corner to the overlay. The expanded view keeps the transcript and results sheet in the same corner, with the orb where it was. Native motion is not yet connected to a system reduced-motion preference, and videos depend on locally available media codecs. PDF and office files can open in their associated app; previews currently show their names and paths rather than rendering pages.

Automatic listening sends when streaming ASR emits end of utterance. In the expanded view, Enter sends the current line and Escape dismisses. A missing microphone ends with a visible error. Silence that never becomes an utterance is not sent. All entry points select `agavai listen`.

The interaction model is covered by `features/ui_design.feature` using Behave and Node.js. Run `PYTHONPATH=src .venv/bin/behave`. In a restricted environment where the current runtime directory is read-only, set `XDG_RUNTIME_DIR` to a fresh temporary directory for the suite; the existing mocked TTS scenarios write runtime logs there. Browser layout and native layer-shell behavior require visual/manual verification separately.

On an Omarchy Wayland desktop, `python3 scripts/check-compact-ui.py` loads the actual overlay in an isolated Quickshell instance and checks native mouse expansion and dismissal, minimization, keyboard-focus settings, corner geometry for every placement, that expanding and minimizing never move the orb, snapshot preservation, and a real focus switch to a second window that receives typing while Agavai minimizes. A second instance checks that a canvas stays expanded through that focus switch and minimizes once a new request clears it. A third checks the recording chip, the live sheet and its controls, the review (playing from a line and correcting one), and opening a recording from the list. It runs against a temporary recording folder, with a stub `agavai` on `PATH` recording what the overlay ran. Pass scenario names to run only some. The checks need the screen on: with the monitors off or the session locked, the compositor renders no frames, so focus and layout checks fail. It shows a brief preview without starting microphone capture.

The `help` native scenario checks the actual session metadata, help toggle, keyboard scrolling, Escape, all corner placements, live snapshot updates and recording bypass text. It is also invoked by `AGAVAI_NATIVE_UI_CHECK=1 PYTHONPATH=src .venv/bin/behave features/pipeline_help.feature`; without that opt-in, only the desktop interaction scenario is skipped. The CLI scenarios use local scripted HTTP services and real request/dispatch/snapshot paths. Set `AGAVAI_UI_SCREENSHOT` to an absolute PNG path to capture the opened help panel. The isolated runtime retains access to the real compositor socket for active-monitor selection.


The UI projects harness state; it owns no authoritative history, inherited tool heads
or executable proposal. `ChatUi.on_harness_event` consumes the UI-independent
[output contract](voice-agent-harness.md#ui-independent-event-interface). The
`session_started` event supplies the session ID to begin_session; entering listening
mode keeps that identity. Raw answer Markdown is rendered only by this adapter. Tool rows receive explicit ok/error/unknown status rather
than inspecting result text. Task/request identity and progress are separate from
tool completion. Recording answers carry source revision and stale-output metadata;
pipeline help records the actual decision/model/source path.
The final `task_status` also carries the serialized `TurnResult`. The adapter
projects its status and leaves content to the preceding answer/display/tool
events, avoiding duplicate rendering. Voice and typed clients use the returned
optional speech text; a silent result never triggers synthesis.
