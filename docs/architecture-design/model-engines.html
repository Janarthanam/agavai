Process boundaries and data flow

Left column: components inside one agavai listen process, kept for the session. Every right-hand box explicitly names another process or service. Rows run top to bottom; the labeled arrows describe both request and return traffic.

LOCAL PROCESS P0 · listener / session controller OTHER PROCESSES · local unless marked remote
1 · CAPTURE PUMP + READER THREADS

Microphone transport

PCM pump and stdout/stderr readers are threads in P0. Metering updates the orb; it never commits a turn.

P1 → P0 · OS stdout pipe · raw audio P1 · PAREC · PER UTTERANCE

PipeWire / PulseAudio capture

Microphone → parec → signed 16-bit little-endian PCM, mono, 16 kHz. Requested capture latency: 20 ms; not an end-to-end measurement.

2 · PLUGGABLE RECOGNIZER ADAPTER

StreamingRecognizer

P0 → P2: uint32 BE length + PCM bytes. Zero length flushes/resets. P2 → P0: newline-delimited JSON {kind, text}.

Events: ready / interim / eob / eou / reset / error. Readiness and reset acknowledgement belong to the lifecycle contract.

P0 ⇄ P2 · stdin/stdout pipes · separate address space

3 · TURN GATE + SESSION STATE

Partial text ≠ committed request

interim / eob → provisional transcript only. eou or Enter → one committed user line. Escape → discard. No router or tool runs on a partial.

Conversation messages, chosen heads and pending confirmations live in P0 memory. Exact session controls may return here without inference. For ordinary turns, health-check P4; if history exists, classify context via P4 before routing.

P0 → ui.json → P3 · file snapshot / FileView watch P3 · QUICKSHELL / OMARCHY OVERLAY · LONG-LIVED

Orb, transcript, tools and results

Reads $XDG_RUNTIME_DIR/agavai/ui.json: phase, partial/final transcript, tool progress, display and reply. This file is presentation state, not the model conversation store. Enter/cancel actions invoke the CLI to signal P0.

4 · PLUGGABLE TOOL-HEAD ROUTER

select(utterance) → list[head_id]

Return up to two head IDs; [] means no tools. Head schemas are selected under the configured tool budget. Routing does not execute anything.

5 · ORCHESTRATOR + LLM HTTP CLIENT

Qwen remains the brain

After the turn gate and routing, run the model/tool loop. Context classification, when needed, used the same P4 server before routing.

P0 sends system/user/history + selected tool schemas. Receives assistant text or tool_calls. Tool results return to the next model call; repeat until a final reply or round limit.

P0 ⇄ P4 · HTTP JSON · 127.0.0.1:18766 P4 · LLAMA-SERVER · SYSTEMD USER SERVICE

llama.cpp engine + selected GGUF

POST /v1/chat/completions, non-streaming. Default model: Qwen3-4B Instruct Q4_K_M. GGUF weights are already configurable; this is not a generic engine adapter.

Needle does not replace Qwen's prose reply or conversation classifier.

6 · ALLOWLIST DISPATCH · IN P0

call_tool(name, arguments)

Checks the named tool, performs the allowed action, publishes results to UI, then appends a clipped tool result to model history. A proposal still follows the existing confirmation contract.

P0 ⇄ child processes · argv/stdout, files and desktop IPC P5… · COMMAND CHILDREN · PER TOOL

hyprctl, Omarchy, fd, grim, OCR…

Some tools are pure Python; others spawn commands that contact desktop services. Returned text/structured results feed Qwen. The voice path calls tools directly in P0; the separate stdio MCP server is only for external clients.

7 · REPLY + SPEECH CLIENT

Final text → speech request

After the tool/model loop: publish assistant text, then send {text, out, voice} as JSON + newline. Await {ok} after a WAV is written. Kokoro failure uses eSpeak, then notification.

P0 ⇄ P6 · AF_UNIX stream · kokoro.sock + WAV file P6 · KOKORO SYNTH SERVER · WARM, 600 S IDLE TIMEOUT

Kokoro-82M + ONNX Runtime CPU

Starts warming near listen/ask. Complete reply synthesis precedes playback; audio is not streamed token by token. Warm synthesis samples: 0.49–0.73 s for the measured short replies.

8 · PLAYBACK OWNERSHIP

Play, cancel, then listen again

Own the audio process group, poll for cancel at ≤100 ms intervals, stop playback and clean up its WAV. Reopen capture for the next turn. Speech barge-in is not implemented.

P0 → P7 · child process argv with WAV path → speakers P7 · PW-PLAY / PAPLAY · PER REPLY

Desktop audio output

Playback duration depends on reply length and follows synthesis. Measured cancel-to-stop median: 54 ms on a silent playback probe; not a guarantee for every system load.

Proposed Needle worker contract

P0 → JSONL {id, utterance, heads}
worker → JSONL {id, head_ids} or {id, error}
startup → ready · shutdown → EOF / terminate

One synchronous request at a time, session-owned process. Needle receives head descriptions as constrained routing choices; its adapter maps function calls back to head IDs. Confidence may be logged for evaluation, but no confidence fast path is part of this design.

Reproducible candidate tests

  • Pin local model and native library files; disable telemetry and hub access (NEEDLE_TELEMETRY=0, HF_HUB_OFFLINE=1, explicit weights and NEEDLE3_LIB_PATH).
  • Set auto_date=False; supply the frozen eval clock explicitly.
  • Record engine/library versions, model hashes, endpoint policy, router and sampling in the eval fingerprint.
  • Compare keyword/Jev/Needle routing separately from Parakeet/Whistle hearing and turn-taking. Remove the eval runner's forced keyword selection for router experiments.
Scope, unresolved decision and source references

This page proposes an experiment architecture; it changes no runtime behavior. Whistle automatic endpointing is intentionally unresolved. Current docs/audio.md forbids restoring silence-timer commits, so this design does not quietly add Silero. Documentation in architecture.md still contains legacy Voxtype/VAD sections; current audio/flow contracts and source take precedence.
