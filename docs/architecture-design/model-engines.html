What becomes replaceable?

BoundaryContract
Speech backendStart → feed audio → finish or cancel. Partial text is optional; one final transcript is required.
Turn-end policyNative EOU, manual Enter, or proposed VAD. Stable words alone never submit a request.
Brain backendHistory + tools in; answer, tool calls, clarification, unsupported or error out.
Runtime selectionChoose a compatible model/runtime pair at startup. ONNX weights, Cactus weights and GGUF are not interchangeable.

Where the time goes

WaitExpected cost
First wordsChunk buffering + decode. Parakeet steps: 160 ms. Whistle suggests ~1 s chunks; faster compute does not remove buffering.
Finish speaking → submitEndpoint wait + remaining decode. Existing eval target: 0.5 s. Whistle unmeasured locally.
Small model handles itSmall inference + tool time if needed. No larger-model wait.
EscalationSmall attempt + larger inference, plus load time if cold.

Whistle is expected to decode faster. Confirm on this Omarchy machine with identical recordings; vendor Apple M4 Pro results are not local latency measurements.

Concrete changes and unresolved choices
  • Split capture/turn control from the Parakeet-specific worker. Give finish and cancel distinct commands.
  • Add Whistle streaming and batch adapters; keep workers warm and reject incompatible configuration at startup.
  • Wrap existing llama calls and add a Needle adapter. Remove mandatory Qwen calls before the small attempt.
  • Run live and replay evaluations through the same adapters; record engine, weights, endpoint policy and hardware.
  • Start Whistle with Enter-to-submit. Automatic VAD needs pause/cutoff evaluation and a deliberate update to the current native-EOU-only specification.
  • Exact small/large model assignments and acceptance rules for general answers remain to be selected.
