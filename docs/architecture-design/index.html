Historical voice-turn design

Agavai turns speech into actions on an Omarchy desktop. A session controller owns the conversation, Parakeet turns audio into text, Qwen chooses actions, and Kokoro speaks the result.

Historical baseline 48f49b3; superseded by the implemented in-process harness design · Markdown design document · models and actions are simulated in this page

1. System2. Ownership3. Turn algorithm4. Recognition5. Deployment6. Failure behavior

What the design must preserve

  • Show speech before acting. Partial recognition updates the screen. Only end of utterance or Enter starts a model turn.
  • Act through named tools. Qwen proposes a function and arguments; the executor decides whether that function exists and runs its implementation.
  • Keep a conversation while listening. Related requests retain context and results; a new topic clears them; dismissal ends the session.
  • Keep inference and execution local. The optional Jev router can send committed text to OpenRouter. Keyword routing removes that model hop.

1 / High-level design

One controller coordinates the whole turn

The microphone and recognizer produce events; they do not run desktop actions. The Session controller accepts a finished sentence and invokes the Turn engine. That engine asks Qwen for a next step, executes any tool calls, and asks again with the results. When Qwen returns an answer, the controller speaks it and reopens capture.

The execution boundary: Qwen never gets a shell and never executes an action. Every proposed call passes through call_tool() and the global DISPATCH allowlist.

2 / Module boundaries

State ownership tells you where code belongs

A session runs from invocation to dismissal. A turn is one committed utterance and its reply. A conversation can reset inside the same session when the topic changes. Mixing these lifetimes would either erase follow-up context or allow cancelled work to reopen the UI.

OwnerState it ownsCode and boundary
Session controllerListener identity, cancellation, current hypothesis, turn ordering; owns the ChatUi instance.__main__.py: listen_session, _await_utterance. Starts/stops capture and calls the turn engine.

These are explanatory states. Runtime thinking covers both reasoning and tool execution. Capture pauses during model work and speech; there is no microphone barge-in. Cancel leads to cleanup and exit from any phase.

3 / Low-level design

How one committed sentence is processed

  1. Resolve the conversation. With prior history, ask local Qwen for exactly follow_up or new_conversation, using no tools. Keep prior state for a follow-up; clear it for a new topic. First turns skip this call.
  2. Select the available actions. The router chooses tool heads such as files or wallpaper. A head is a schema group, not another agent. Merge relevant prior heads and advertise up to eight schemas by default.
  3. Run the model/tool loop. Send system prompt, history, user text and schemas to local Qwen. For tool calls, dispatch each call in order, append matching tool-result messages, and request the next completion. A missing head gets one retry; default limit is six model rounds.
  4. Publish and speak the answer. Full results become typed canvas items. Model results are shortened; speech uses readable names without paths or extensions. Remember the conversation, speak the reply, and return to listening.
on committed_text:
  check local model health
  if history exists:
    classify follow_up / new_conversation
    clear conversation if new
  schemas = route(text) + relevant prior heads
  messages = system + history + text
  repeat up to max_tool_rounds:
    response = Qwen(messages, schemas)
    if response has no tool calls:
      remember and return spoken answer
    attach missing head once, if needed
    otherwise run each allowlisted call
    publish full results to canvas
    append short results to messages

The wallpaper “show me” path also ensures wallpaper_list produces a gallery, including when Qwen only asks the user to choose an image. This is an existing special case, not a general tool planner.

Follow an actual use case through those boundaries

    The same result has two representations

    Canvas: actionable local data

    {kind: "file", title: "budget_notes.md",
 path: "/home/user/Documents/budget_notes.md",
 uri: "file:///home/user/Documents/budget_notes.md",
 openable: true, preview_html: "…"}

    The UI needs a path to preview or open the file. Explicit ui-open validates session id, selected item and supported type before calling xdg-open.

    Model and speech: readable names

    {type: "Files", count: 1,
 items: [{kind: "file", name: "budget notes"}]}

    Typed results enter model context as kind/name, clipped to 500 characters. The spoken reply summarizes a list and points to the canvas.

    UI identity matters: session_id controls dismissal; a new display.id identifies newly published results and opens their canvas. Returning to listening or retaining a display does not undo manual minimization.

    4 / Recognition algorithm

    Parakeet emits the boundary that commits the turn

    The worker keeps one continuous signal and recurrent state across microphone packets. Packet ends are not word or sentence boundaries. Every 16 new mel frames advances the cache-aware encoder; a greedy RNN-T decoder emits text and learned markers.

    Interim / EOB
    Replace the partial line. Keep listening. Do not call a model or tool.

    Nonempty EOU / Enter
    Commit once. Reset the recognizer, pause capture, and run the turn engine.

    Empty EOU / cancel
    Empty EOU leaves capture open. Cancel drops the hypothesis and exits.

    The orb's RMS meter reads the same PCM and never decides a turn. F9 dictation is separate from the automatic assistant path.

    5 / Physical design

    Logical modules share a process; models do not

    The session controller, context decision, router, turn engine, tool dispatcher, canvas and snapshot writer are functions in one Python process. ASR and speech use a separate Python environment for inference dependencies. Qwen stays loaded in an independently supervised service.

    Startup order: review TOML → validate llama-server → download chosen models → register plugin/launcher/service → start Qwen. On invocation: summon the existing plugin → create the guarded listener → load ASR → begin capture and warm Kokoro. Dismissal ends the listener and ASR; the plugin and Qwen remain, and Kokoro can remain warm.

    Auxiliary interfaces and extension points

    agavai ask starts a blank, one-shot turn with no microphone and blocking speech. It shares the snapshot path with listening; those writers are not coordinated.

    agavai mcp is a separate stdio JSON-RPC 2.0 adapter: initialize, tools/list, tools/call. It exposes the same 35-tool global registry and calls the same dispatcher. The built-in voice loop bypasses MCP. The A2A card is local discovery metadata, not an agent RPC service.

    To add a desktop capability, add its named function, schema and DISPATCH entry in tools.py, associate it with a head in heads.py, and add a canvas normalization only if it produces a new result type. Keep timing policy in the session and recognition state in the worker. Changing a model/provider belongs in configuration and the model runner.

    Mail, calendar, persistent memory, external MCP tool consumption and pixel-based computer use are not implemented by this runtime. The proposed evaluation design includes those future capabilities; it is not the current component architecture.

    6 / Reliability

    Recover at the boundary that owns the failure

    FailureResultOwner / implication
    Shell, microphone or ASR startup failsNo turn is fabricated. Summon failure prevents listener start; capture/ASR failures show an error and end listening.Entry / session. No automatic legacy voice fallback.
    Context decision is invalidKeep earlier results/history and surface the error. Do not route or execute this request.Turn engine. Clearing state must follow a valid decision.
    Jev is unavailableUse keywords unless fallback=none. Empty remote choices can also use keywords.Router. Remote routing is optional.
    Qwen or a tool failsHTTP errors surface; tool failures return strings to the next model step. Exhausted rounds return an explicit failure.Turn engine / executor. No HTTP retry or action rollback.
    Kokoro failsTry eSpeak, then a notification, following configured preference.Speech controller. Preserve a response path.
    User cancelsMark dismissed session, create cancel marker, signal listener, stop owned Kokoro playback and discard later snapshots.Session + snapshot. Blocking HTTP/tools/synthesis can delay cleanup; already finished actions stay finished.

    Performance contract: one user, serial voice turns, llama-server --parallel 1. Defaults bound routing to 2 s and each completion to 120 s, with six model rounds; they are failure limits, not acceptable response-time targets. No measured end-to-end SLA is established. F9 microphone exclusion and typed/voice writer exclusion are also not enforced.

    Diagnostics: agavai status for state/model health, the user-service journal for Qwen, ui.json for the latest transcript/tool/phase, and kokoro-serve.log for speech. Detached listener stderr is discarded and route/context verdicts are not traced.
